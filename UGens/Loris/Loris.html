About Loris


Loris is an Open Source sound modeling and processing software package based on the Reassigned Bandwidth-Enhanced Additive Sound Model. Loris supports modified resynthesis and manipulations of the model data, such as time- and frequency-scale modification and sound morphing.


For more information about Loris and the Reassigned Bandwidth-Enhanced Additive Model, contact the developers at loris@cersloundgroup.org, or visit them at http://www.cerlsoundgroup.org/Loris/.


The primary distribution point for Loris is SourceForge (http://loris.sourceforge.net) and its mirrors.


Loris in SC


Loris' analysis facilities are not optimised for realtime use. Users can however produce SDIF files with RBEP format frames in advance using the loris-analyze command line tool, or a third party program like SPEAR. In SC synthesis facilities are provided through two classes, BEPartials and RBE_SDIF_File, which are used to import and access loris partial data, and two UGens, BEOsc and LorisPhaseGen, which in combination with other UGens can be used for resynthesis.


BEOsc is similar to a normal sine oscillator, but with an additional bandwidth input, which is used to control a modulation process using filtered noise. Together these can be used to do oscillator bank resynthesis of both the pitched and noisy parts of a spectrum.


Varying partial parameters of frequency, amplitude, and bandwidth are are represented with Envs in SC, and EnvGens are used to drive the inputs of BEOsc. This allows for maximum flexibilty, since the parameters are subject to the same possibilities for manipulation as any SC UGens. Partial phase is a special case, and requires customised handling:


LorisPhaseGen is a variant of EnvGen which is used to drive the phase input of a BEOsc. Loris analysis allows for the 'collation' of partials, i.e. combining non-coincident partials into one so as to save resources and reduce the overall number of partials. Collated partials are silent in between. In oscillator bank resynthesis one normally worries only about initial phase, but collated parials require a phase reset when partials transition from zero to non-zero amplitude, i.e. onsets. BEOsc treats a phase input of -inf as a special value, meaning advance phase according to frequency. With a correctly formatted Env LorisPhaseGen outputs phase values only at partial onsets, and outputs -inf otherwise.


BEPartials has an ar method which returns an Array of UGens for controlling frequency, phase, bandwidth and amplitude. 


N.B. Since the number of partials in a Loris analysis may be very large (numbering at times in the thousands), it may be necessary to tweak analysis parameters to reduce them in order to make realtime synthesis possible. Collation is one way to do this, but it is also possible to access and edit the partial list of a BEPartials directly, which could allow one to thin the list on the basis of amplitude, duration, etc. Similarly, each partial requires three EnvGens, one LorisPhaseGen, and a BEOsc, which can result in very large and complicated SynthDefs. For this reason it may be necessary to increase the numWireBufs in your ServerOptions, and to use load rather than send when sending a SynthDef to a Server.


Examples


s.boot;

f = RBE_SDIF_File("A.sdif".resolveRelative); // open a SDIF file with RBEP frames

p = BEPartials(f);



(

SynthDef(\A, { arg stretch = 1, pitch = 1, bw = 1, mul = 1, gate = 1, attack=0, release=0.1, out=0;

var outmix, envs;


// returns [[freqEnvGen, a LorisPhaseGen, bandwidthEnvGen, ampEnvGen] * numPartials]

envs = p.ar(stretch, pitch, bw); 


// pan each partial and mix

outmix = Mix(PanAz.ar(2, BEOsc.ar(*envs), {LinRand(-1, 1)} ! envs[0].size)) 

* EnvGen.ar(Env.linen(attack, p.dur * stretch, release), gate, mul, doneAction: 2);

Out.ar(out, outmix); 

}).load(s, dir: "".resolveRelative);

)


Synth(\A);

Synth(\A, [pitch: 0.5]);

Synth(\A, [stretch: 3]);

Synth(\A, [stretch: 3, bw:0]);

Synth(\A, [stretch: 3, bw:2]);





// inputs can be other UGens

// works well for stretch

(

SynthDef(\Astretch, { arg pitch = 1, bw = 1, mul = 1, gate = 1, attack=0, release=0.1, out=0;

var outmix, envs;


// normal onset, then hold....

envs = p.ar(EnvGen.kr(Env([1, 1, 10], [0.1, 0.05])), pitch, bw); 


// pan each partial and mix

outmix = Mix(PanAz.ar(2, BEOsc.ar(*envs), {LinRand(-1, 1)} ! envs[0].size)) 

* EnvGen.ar(Env.linen(attack, p.dur * 10, release), gate, mul, doneAction: 2);

Out.ar(out, outmix); 

}).load(s, dir: "".resolveRelative);

)


Synth(\Astretch);

Synth(\Astretch, [pitch: 0.5]); // hello cello





// can use Functions for BEPartials:ar

// wobble partial pitch

(

SynthDef(\ApitchWobble, { arg stretch = 1, pitch = 1, bw = 1, mul = 1, gate = 1, attack=0, release=0.1, out=0;

var outmix, envs;


// randomly modulate pitch per partial

envs = p.ar(stretch, {SinOsc.kr(LinRand(4.0, 10.0)).range(0.995, 1.005)}, bw); 


// pan each partial and mix

outmix = Mix(PanAz.ar(2, BEOsc.ar(*envs), {LinRand(-1, 1)} ! envs[0].size)) 

* EnvGen.ar(Env.linen(attack, p.dur * stretch, release), gate, mul, doneAction: 2);

Out.ar(out, outmix); 

}).load(s, dir: "".resolveRelative);

)


Synth(\ApitchWobble, [stretch: 3]);





// rand pitch

(

SynthDef(\ApitchRand, { arg stretch = 1, pitch = 1, bw = 1, mul = 1, gate = 1, attack=0, release=0.1, out=0;

var outmix, envs;


// randomly scale pitch per partial with global scale

envs = p.ar(stretch, {LinRand(1.0, 2.0) * pitch}, bw); 


// pan each partial and mix

outmix = Mix(PanAz.ar(2, BEOsc.ar(*envs), {LinRand(-1, 1)} ! envs[0].size)) 

* EnvGen.ar(Env.linen(attack, p.dur * stretch, release), gate, mul, doneAction: 2);

Out.ar(out, outmix); 

}).load(s, dir: "".resolveRelative);

)


Synth(\ApitchRand, [stretch: 3]);

Synth(\ApitchRand, [stretch: 3]); // different every time

Synth(\ApitchRand, [stretch: 3, bw: 0]);

Synth(\ApitchRand, [stretch: 3, pitch: 0.5, bw: 5]);
