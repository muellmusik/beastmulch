BMControl represents a single control


Inherits from: Object


BMControl represents a single control, such as a hardware fader or knob.


See also: Object [some other help files]


Controllers vs. Controls


The BEASTmulch provides two ways of dealing with a given control:


1) as a collection of controls - this will be a subclass of BMAbstractController and will generally represent a single hardware device and all of its controls. Controls should be numbered, and be accessible through getVal and setVal by index, usually starting with 1 for human readability.


2) as an individual control - an instance of BMControl. These have a Symbol for a name, and can be accessed through the class methods *getValueByName and *setValueByName.


It is sometimes useful to deal with one or the other representation depending on what one is trying to do. BMAbstractController has two classvars, allControllers and allControls, which contain dictionaries. These allow objects to query any individual control or controller by name, or to get global information about what controls or controllers currently exist.


Each controller allocates a multichannel control rate bus for its controls. Objects in the library map to controls by mapping synth Contols to the corresponding bus. Bus values are assumed to be between 0 and 1. On Cmd-. all mappings are cleared.
